# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

「推しVTuberを落とせ！」 (formerly 「おつハル！」; おつハル is still Haru's sign-off line in the story): a 30–40 min romance sim for smartphone browsers. The player is a listener of the original VTuber 天音ハル (real name 春川ひなの). Static HTML + vanilla JS ES modules, no build step, published with GitHub Pages from the repo root (`.nojekyll` present). No npm dependencies; three.js 0.180 + @pixiv/three-vrm 3.4.5 are loaded from jsDelivr via the import map in `index.html` (keep `test/vrm-check.html` in sync).

## Commands

- Serve locally (no Node/Python on this machine): `powershell -ExecutionPolicy Bypass -File tools/serve.ps1` → http://localhost:8080/
- Tests: open http://localhost:8080/test/ — validates `data/scenario.json` and plays 7×3000 simulated games (also prints the real-life personality distribution) (random, no-out, mostly-good = right 75% of the time, always-good, tipper = always 💰, joker = always 🤪, forced rares) and prints the ending distribution — use it for balancing. Headless run:
  `& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --headless=new --disable-gpu --user-data-dir=<scratch dir> --virtual-time-budget=120000 --dump-dom http://localhost:8080/test/` and look for `すべて成功`.
- URL options: `?debug=1` (affection/mood/choice types), `?seed=N` (fixed RNG), `?rare=all` or `?rare=cat,pin` (rare *endings* are forced only by name: `?rare=neochi`, `?rare=gyaku`), `?vrm=0` (SVG avatar).
- Note: headless Edge does not advance CSS transitions under `--virtual-time-budget`, so transitioned values (e.g. the heart meter) look stuck in headless screenshots only.

## Architecture

- `data/scenario.json` — `rules`, `personas`, `realPersonas`, `moods`, `spice`, `epilogue`, `omake`, `listenerTypes`, `voice`, `mob` comments, `rares`, `routes`, `endings`; `chapters` lists `data/chapters/ch1..5.json` (inlined by `js/data.js`). Lines are `{who: haru|me|mob|narr|sys, text, face, motion, if, by}` or commands `{cmd: flag|set|face|motion|wait|pop|affection|reveal|persona|blackout|bgm}` (`pop` takes `silent: true`; `blackout` fades to black with `text` and waits for a tap). `{name}` / `{call}` / `{viewers}` / `{subs}` are substituted. `by: {queen: {text, face}}` overrides a line for a persona (a realPersona key wins over the VTuber persona). Settings (`set`/`defaults`) also take `contact` = name in the DM header / call screen. Conditions (`if`): mood, flag, notFlag (both accept a list: all / any), minAff/maxAff, chapter (number or list), persona/notPersona, real/notReal, minPop/maxPop, minPeak/maxPeak (highest pop reached, `state.peakPop`), minGesu, revealed. Design doc: `docs/scenario-outline.md` (v0.2).
- Stats: affection (hidden until `{cmd:"reveal"}` at the ch3 DM — no meter, no popups before that; `chapter.affScale` 0.5 in ch1–2 halves every change while hidden so the meter appears around 50–70, not maxed; gates: DM 30 at 2-6, meet 60 at 3-7, 72 at 5-2, confession `rules.loverMin` 85 / joke `loverGagMin` 90, 85 for geinin/itazura; the 5-4 lines and lover endings vary by affection (≥95 / ≥98 / ≤89 / ≤84), and a confession that falls short by ≤ `rules.nearMiss` sets flag `near_miss` for its own friend-ending lines), pop 0..100 (`js/stats.js` maps it to viewers/subscribers), persona angel/queen/geinin. Each choice has a style (`style`, else `rules.typeStyle`: good/normal→kind, gag→neta; superchats are `"style":"mitsugi"`), which adds `rules.stylePop` popularity (only while the UI mode is `stream` — DMs, calls and dates never move popularity) and counts toward the chapter's persona vote (`updatePersona` at chapter end, margin `rules.personaMargin`). `personas[p].styleMod` adjusts affection by style; Chapters 4–5 (`"real": true`, `evalPersona: false`) are the dates: there `realPersonas[realPersona].styleMod` replaces the VTuber one. `realPersona` (ひなの off stream: shy → amae/shikkari/itazura) is re-voted by `{cmd:"persona"}` (after 4-4 and 5-2) from the styles since the last vote; `variantBy: "real"` picks scene variants by it. Endings with `"epilogue": true` (lover, lover_queen, lover_geinin, gyaku) then play `data.epilogue` (HUD title エピローグ): blackout → 5th-anniversary stream, big (peak pop ≥ 65, flag `epi_big`, pop set to 100) or modest → home together, proposal. `routes` remap endings by persona/pop/flags (lover→lover_queen/lover_geinin, listener→atm/nyanko/star, friend→zarigani/aikata).
- `js/engine.js` — DOM-free scenario runner (also used by the test page with fakes). Scene flow: scene `if`/`chance` → rareEnd(start) → topic or `variantBy:"persona"` variant → lines → mood hint → generic rares (`at:"before"`) → cat → rareEnd → choice → after → slip → generic rares → gate. Choice types: good / normal / bad / trap (💣 sounds nice but is heavy or pushy, default −8) / gag / out. `drawChoices` shows `rules.choiceCount` (5) options: always one 💗 good, one 🤪 gag, one 💰 mitsugi and one 💣 trap if any, a ☠️ out with probability `outRate`, then fills and shuffles. In stream mode one slot always holds a `spice` comment (net meme 🤪 / creepy or dirty 💀 / over-the-line ☠️ → `sekuhara`, odds `rules.spiceRate`; the 🤪 slot takes a meme when a ☠️ fills the free slot; `choice.noSpice` disables it). Creepy/dirty spice picks count in `state.gesu`: `rules.gesu.warn` plays at limit−1, `rules.gesu.limit` (3) ends with `mikudashi`. `topic: true` draws one of `scene.variants`; `topic: "events"` draws from the chapter-level `topics.events` pool (ch1 1-2 draws 1 of 8 stream contents (1-6 shares the original 4 keys on purpose); ch1 1-3..1-5 draw 3 of 12 events; ch2 2-2 draws 1 of 5 — membership / new outfit / first sponsored stream / online meet-and-greet in call mode / horror watch-along; ch3 3-2e and 3-5e draw 2 of 8 DM/call events; ch4 4-3 draws 1 of 4 first-date spots (arcade / karaoke / bookstore / cinema) and ch5 5-1 1 of 3 second dates (aquarium / planetarium / zoo — real-persona flavour via `by` and `real` conditions); no repeats via `state.topicsUsed`, so keys must be unique across chapters — the test page checks this); `scene.intro` lines play before the drawn variant. A scene with `"end": "id"` always ends the game after its lines (bad-ending branches). Drama arcs: ch2 `2-4s` (pop ≤ 40 slump) → `2-4t` sensitive ASMR stream (flag `ero1`, also forced by 2+ dirty comments) → `2-4u`/`meisou` unless rescued (`ero_saved`); per VTuber persona (ch2 setup → ch3 crisis call; `X_warned` from the ch2 scene makes her recover even if the player enables her in ch3): queen `2-3q` spa-ranking → `3-4q` flame (`queen_humbled` apology stream, or `queen_fall` → `3-4r`/`enjou`); angel `2-2a` reply-to-everyone endurance → `3-4a` 4 a.m. call (`angel_rest`, or `angel_fall` → `3-4b`/`moetsuki`); geinin `2-2g` dares → `3-4g` can't say what she feels (`geinin_honest`, or `geinin_fall` → `3-4h`/`piero`). Every run: ch5 `5-1c` the day after the second date fans post a sighting on stream (noSpice; teasing → flag `crisis_worse`, outing yourself → `nioase`) → `5-1d` call "should we stop meeting?" (`crisis_ok`, or `crisis_break` → `5-1e`/`surechigai`). Ending category `bad` = バッドエンド. `scene.rareEnd` `{ending, chance, if?, at?: "start"}` ends the game early with a `cat: "rare"` ending (寝落ち 0.3% at 1-0, 逆告白 5% at 4-4 when affection ≥ 95). Rares other than cat/slip/pin/tategaki are generic `{chance, at, if, lines}` events.
- `js/rng.js` — seeded mulberry32. All gameplay randomness goes through it; cosmetic randomness (mob comments, blink) uses `Math.random`. The game autosaves state (incl. `rngState`) at each scene start, so resuming replays the same draws.
- `js/stats.js` — pop → viewers/subscribers. `js/data.js` — loads scenario.json + chapter files.
- `js/ui.js` — DOM layer with four layouts toggled by class on `#screen-game`: `mode-stream`, `mode-dm`, `mode-call`, `mode-adv`. The stream/DM choice sheet repeats the last Haru/narration line (`lastLine`) and scrolls on short screens; the menu has a backlog (`ログを見る`, `ui.log`, current session only). ⏩ `#btn-skip` = read-skip: every line has `key` (`lineKey(who, raw text)` in the engine); read keys persist in localStorage (`otsuharu.read.v1`, state.js `loadRead/saveRead`); while skipping, read lines/cards/blackouts advance automatically, the first unread line or a tap stops it, choices keep it on. Backgrounds `station`/`cafe`/`arcade`/`sunset`/`aquarium`/`park`/`karaoke`/`honya`/`cinema`/`planetarium`/`zoo` load `img/bg/<name>.(jpg|webp|png|svg)` (first found) into `--bg-img`, drawn blurred over the CSS gradient by `.stage-bg::after`; other backgrounds are gradients only.
- `js/avatar.js` — `PlaceholderAvatar` (SVG) and `Avatar`, the wrapper used by the game: it shows the SVG and lazily imports `js/avatar-vrm.js`; once the model loads the host gets class `has-vrm` and the canvas replaces the SVG. Interface: `setModel` (`vtuber`/`real`/`none`), `setExpression`, `setTalking`, `playMotion`, `speakChar` (UI passes each typed character of Haru's lines).
- `js/avatar-vrm.js` — one shared WebGL renderer + VRM cache; each frame the canvas moves to the visible `VrmView` (title or game). Maps game expressions to VRM presets, lip sync = kana → vowel viseme (aa/ih/ou/ee/oh, kanji random), blink, idle sway, motions via bones. Camera: bust shot, face close-up when the host is square (call screen).
- `models/Vtuber_red.vrm` — the VTuber model (VRoid, by the user). `models/Human_red.vrm` — the real-life model (VRoid, by the user). `models/sample.vrm` — pixiv sample, no longer used by the game (handy for `test/vrm-check.html?model=sample.vrm`). Bust framing uses the model bounding box top (`topY`) so tall hair/ears are not cut. Model URLs are `VRM_MODELS` in `js/main.js`; `?vrm=0` forces the SVG. `test/vrm-check.html` renders a grid of expressions/visemes/motions.
- `js/sound.js` — all audio synthesized with Web Audio (no files): procedural BGM loops `title`/`stream`/`night`/`date` (UI picks by mode/background), special tracks `confess`/`crisis`/`epilogue`/`bad` (scene `"bgm"`, ending `"bgm"`, `{cmd:"bgm"}`, bad endings default to `bad`; `ui.setBgm` override, cleared at each scene start) and SEs. Unlocked by `sound.bindUnlock()` on pointerdown/touchend/click/keydown (iOS only counts touchend/click as a gesture; also resumes the iOS `interrupted` state and sets `navigator.audioSession.type = 'playback'` so the silent switch does not mute it); mute toggle (`.sound-toggle`) saved in localStorage. Haru voice clips: `data.voice` (byFace, rate, cooldownMs, clips) → files `voice/<key>_<n>.mp3` (missing files are skipped; list in `voice/README.md`). Without a recorded clip, Haru's typed lines play talking blips (`sound.blip(ch, {face, tone})`: one short note per character, pitch fixed per character on a pentatonic step, `BLIP` table per expression; tone `vtuber` = triangle / `real` = softer sine, from `haruName`; not in DM mode or while skipping; a clip that actually plays suppresses blips for that line). Engine `voiceFor(line)` picks the key from the line's `face` or an explicit `voice` (string forces, false suppresses); not played in DM mode.
- `js/main.js` — screens, gallery, how-to-play pages (`#screen-howto`, 5 swipeable pages in `index.html`; title「あそびかた」, and shown automatically before the first new game — `hasSeenHowto/markHowtoSeen` in state.js — then the name entry), ending share (X intent + Web Share API / clipboard; the shared URL is `share/<id>.html`, a static page with that ending's og:image `img/share/<id>.jpg` that forwards to the game, and the native share attaches the image when the device can share files), replay rewards (title「章をえらぶ」starts any chapter reached before from the state saved at that chapter's start — `saveChapterSnapshot` in state.js — with fresh random draws; `data.omake` bonus scenes unlock in the gallery at `need` endings or `"all"` and play through `Engine.playLines`; the ending screen announces new unlocks), sound toggle. OGP tags are in `index.html`; `img/ogp.png` (1200×630) is a render of the VTuber VRM + title logo.
- `js/listener.js` — listener-type result: the engine counts `state.styleTotals` (kind/mitsugi/neta over the whole game) and `state.typeCounts`; `data.listenerTypes` (first match of minShare/maxShare/minMiss/maxMiss/minGesu, last entry = fallback) is shown on the ending screen (hidden under 3 styled choices), added to the share text, and drawn under the ending card in the native-share image.
- `js/state.js` — localStorage save + gallery (endings/rares), read lines, chapter snapshots, last handle, how-to flag; all access is try/catch guarded.
- `tools/make-share.mjs` + `tools/share-card.html` — regenerate the per-ending share images and pages after adding or renaming endings (needs Node + Playwright and the local server: `node tools/make-share.mjs [ids…]`).
- `docs/scenario-outline.md` — design doc agreed with the user (story, choice tables, endings).
